## 0. 用户定案

上一刀把「过程卡 + 终稿文本」当成交付，用户明确否定：「我要的是卡片，不是直接发。」
本刀改为：**一张卡片同时承载过程与最终答案**，收尾编辑同一张卡到终态；只有卡片编辑失败
才降级发一条文本。

## 1. 改动

### 1.1 运行中：过程卡恢复承载正文尾部

- `ProgressCardInput.tail` 恢复；`progressCard` 在状态行、`最近：` 行之后渲染正文尾部
  （`tailText`，预算 8 KB），仍走 400 ms 节流；卡片尺寸由 `assertCardFits` 保护。
- 状态行保持上一刀格式：会话标题 · 状态 · 步数 · 工具 · 已运行 · 最近事件。
- 底部提示改为 `_过程消息；收尾会把终稿更新到本卡。_`。

### 1.2 收尾：编辑同一张卡到终态（不再发文本）

- 新增 `finalCard()`：状态行改为终态（完成/失败/已中断/待审批）+ 完整正文；
  卡体超过 30 KB 时保留尾部，开头写 `…已省略 N 字符`（UTF-8 安全，按码点计数）。
- `Bridge#settleTurn`：
  1. 取 `state.lastOutput` 作完整正文（为空则写「本轮已结束（状态）」）；
  2. 取当前过程卡的 `messageId`（第一张卡），flush + dispose 其流；
  3. 用 `transport.updateCard(messageId, finalCard)` 就地定格同一张卡；
  4. **不再调用 `sendFinal`**（该函数已删除）。
- 一个回合对外只有 1 个 `message_id`（首张卡）+ 若干次 patch；无第二条正文消息。
- 终态提示（error/interrupted/blocked）仍单独发一条文本，这是提示不是正文，不受影响。

### 1.3 降级唯一出口

- 卡片编辑失败（`updateCard` 抛错；无卡可编辑时首卡创建也抛错）才调用
  `#finalFallback`：
  - 用 `finalCardPlainText()` 生成与卡一致的内容（状态行 + 完整正文）；
  - 发一条文本（`replyText` / `sendText`）；
  - 记日志 `final fallback to text: <reason>`。
- 成功路径绝不发文本；降级路径只发一条，不双发。

## 2. 测试

- 原有 180 例全部保留（其中回合收尾/终态/终稿标题等用例按「同卡编辑」语义适配，
  覆盖意图不变），新增 3 例，共 **183 例全绿**：
  - `卡片编辑失败才降级发一条文本，内容与卡一致并记日志`（强制 `updateCard` 失败；
    断言只有 1 条文本、含正文与终态、日志有 `final fallback to text:`）；
  - `超长正文：终态卡 ≤30KB、保留尾部并写「…已省略 N 字符」`（UTF-8 安全、头尾标记）；
  - render：`终态卡：完整正文入卡；超 30KB 保留尾部并写「…已省略 N 字符」`。
- 既有用例适配摘要：
  - `回合收尾：编辑同一张过程卡到终态，不另发文本`：`updateCard` 被调用、
    内容含完整正文、`sendText`/文本消息为 0、只有 1 个 message_id；
  - 终态 error/interrupted/blocked：答案在卡内，唯一文本是主动提示；
  - 终态卡带/无标题：正文与标题都从卡里断言，不再找终稿文本；
  - `同一回合助手正文只在卡片内出现一次（同 message_id）`。
- 全部注入式（假 transport/agents/clock），不碰真飞书与真实数据。
