## 0. 背景

上一刀把状态卡合并进了过程卡，砍错了：两者时间尺度不同——
过程卡 = 一个回合（`turn/start` 建、`turn/end` 定格）；
状态卡 = 一个会话（常驻、跨回合）。且状态卡每个 scope 只有一条、靠 patch 原地更新，
不会增加消息数。

## 1. 改动

### 1.1 恢复状态卡（每 scope 一条，patch 更新）

- `ScopeState.statusStream` 恢复；每个 scopeKey **首次活动**（第一条入站消息）时创建一条
  状态卡，之后所有更新都 patch 同一 `message_id`，绝不重发。
- 内容（无助手正文）：
  - `会话：<标题或「标题生成中」>`
  - `状态：空闲 / 运行中 / 等待输入 / 完成 / 失败 / 待审批 / 已中断`
  - `步数 N（工具 M）`
  - `最近事件：<type>`
  - `更新于 <相对时间>`（`sessionTimeLabel`）
  - `会话 ID：<尾 8 位>`
- 标题到达、agent 就绪、`/new`、`/resume`、回合事件都会刷新；`turn/end` 后显示终态。

### 1.2 过程卡保持现状

- 每回合一张，承载状态行 + 正文尾部；`turn/end` 定格在同一张卡（不发文本）；
  正文唯一性、30 KB 上限、编辑失败降级逻辑均不变。

### 1.3 顺序与共用节流预算

- 新回合：先 `#renderStatus` 确保状态卡存在/更新，再创建/更新过程卡。
- 新增 `CardPatchBudget`：一个 scope 内过程卡与状态卡共用同一 400 ms patch 窗口；
  首次创建不占预算，之后任一张卡 patch 都会消费窗口，另一张自动延迟到窗口打开，
  避免双倍打 API。`CardStream` 的既有节流语义（无 budget 时）不变。

### 1.4 配置开关与降级

- `BridgeConfig.statusCard?: boolean`，默认 `true`（`config.ts#DEFAULT_STATUS_CARD`）。
  `false` 时 `#renderStatus` 直接返回：不创建/不更新状态卡，其余行为不变。
- 状态卡创建/更新失败：`CardStream.onError` 记 `status card degraded: <reason>`，
  标记 `statusDegraded`，不抛出、不影响回合主流程；流保留，下个事件 `set` 会重试
  （创建失败时 messageId 仍为空；更新失败时 lastSent 未推进）。

  - `statusCard=false：不创建状态卡，过程卡与收尾不受影响`；
