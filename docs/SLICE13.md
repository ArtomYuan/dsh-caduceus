# 第十三刀：消除「同一个答案出现两次」（过程卡去正文 + 卡片合并）

状态：**代码与单测完成；需按宿主流程同步并重启后验证**。
本刀未改 `docs/DESIGN.md`、未安装/未重启、未触碰真实数据。

## 0. 现象与根因

真机截图：过程卡里已是完整回答，紧接着又收到一条一模一样的文本消息。

根因：`src/render/cards.ts` 的 `progressCard()` 把助手输出尾部（≤8 KB）放进卡片
（`input.tail`）；`Bridge#settleTurn` 收尾时又把同一份 `state.lastOutput` 当终稿新发。
短回答因此被完整重复两次。另外每轮同时发过程卡与状态卡，信息也重叠。

## 1. 改动

### 1.1 过程卡不再承载正文

- 删除 `ProgressCardInput.tail` 与卡片里的正文 `div`；`progressCard` 不再走
  `tailText` 渲染任何助手文本。
- 过程卡仅保留两个内容行 + 底部提示：
  - 状态行：`[会话：<标题> · ]**<状态>** · 步数 N · 工具 M · 已运行 Xs`；
  - `最近：<工具名或事件>`（按 Unicode 码点截断 ≤40 字）；
  - `_过程消息；收尾会另发一条终稿。_`
- 标题/最近事件均做 40 字截断，卡片仍受 30 KB 上限保护。

新的过程卡元素构造：

```ts
const stateLine: string[] = [];
if (sessionTitle) stateLine.push(`会话：${clipLabel(sessionTitle)}`);
stateLine.push(`**${input.stateLabel}**`, `步数 ${input.steps}`, `工具 ${input.tools}`);
if (input.startedAt !== undefined) stateLine.push(`已运行 ${seconds}s`);
const elements: FeishuCardElement[] = [
  div(stateLine.join(' · ')),
  div(`最近：${clipLabel(input.recentEvent ?? '（无）')}`),
  div('_过程消息；收尾会另发一条终稿。_'),
];
```

### 1.2 终稿唯一承载正文

- `Bridge#settleTurn` 逻辑不变：`turn/end` 后新发一条文本（`message_id=None`），
  绝不编辑过程卡；标题就绪时首行 `▸ {标题}`、空行后接正文。
- 过程卡不再包含正文，因此短回答只出现一次。

### 1.3 删除冗余双卡，合并为一张

- 删除 `ScopeState.statusStream` 与 `Bridge#renderStatus`；每轮只创建/更新过程卡。
- 状态信息（标题、状态、步数、工具、已运行、最近事件）全部并入过程卡状态行；
  状态模板颜色仍按状态走（running 蓝、completed 绿、failed 红…）。
- `statusCard()` / `statusCardLines()` 保留为导出（兼容旧调用），但桥接层不再发送；
  `/status` 命令输出（`statusText`）保持不变。
- 标题到达、`/rename`、agent 就绪后的重渲全部改为 patch **同一张过程卡**。

## 2. 测试

- 原有 178 例全部保留（其中 4 个卡片相关用例按新语义适配：只发一张过程卡、
  标题 patch 过程卡、首行以「会话：标题」开头；覆盖意图不变，未删除/弱化），
  新增 2 例，共 **180 例全绿**：
  - `合并后过程卡只发一张，含状态/步数/最近事件（不再有独立状态卡）`；
  - `同一回合内助手正文只出现一次（过程卡/补丁 + 终稿）`——收集该回合所有
    卡片创建、卡片 patch 与文本消息，断言助手正文的每个完整句子在全集内恰好出现 1 次，
    且过程卡里一次都不出现。
- `render.test` 中过程卡用例改为断言「不承载正文 + 状态/最近事件 + ≤30KB」。
- 全部注入式（假 transport/agents/clock），不碰真飞书与真实数据。
